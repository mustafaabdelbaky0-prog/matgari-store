# متجري — أبليكيشن إدارة متجرك الأونلاين

أبليكيشن ويب بسيط (بيشتغل من المتصفح زي تطبيق موبايل، وممكن "تضيفه للشاشة الرئيسية") لأي حد بيبيع أونلاين ولسه مش عارف يبني لاندنج بيدج أو يحسب مكسبه وبيعه.

## الفكرة

1. التاجر بيسجل حساب ويختار مجاله (ملابس أطفال، عطور، إكسسوارات... إلخ).
2. بيضيف منتجاته (اسم، صورة، سعر شراء، سعر بيع مقترح تلقائيًا، كمية).
3. أي منتج بيضيفه بيظهر أوتوماتيك في صفحة بيع عامة (لاندنج بيدج) بتتولد له لينك خاص بيه يقدر يشاركه مع عملائه.
4. بيسجل مبيعاته ومشترياته، والأبليكيشن بيحدّث المخزون والخزنة (رصيد الفلوس) أوتوماتيك.
5. زرار "اطلب الآن" في صفحة البيع بيودّي العميل لواتساب التاجر مباشرة — مفيش احتياج لبوابة دفع أو شحن معقد، تمامًا زي فكرة إيزي أوردر بس أبسط بكتير.

## مميزات تقنية مهمة

- **مبني على Node.js الأساسي (`http`) من غير أي إطار عمل (framework)** — راوتر وقوالب HTML بسيطة مكتوبة يدويًا، مش Express ولا React.
- **قاعدة بيانات: Neon Postgres (serverless عبر HTTP)** — مناسبة لبيئة Vercel اللي بتشتغل بـ serverless functions (من غير نظام ملفات دائم، عكس SQLite المحلي اللي كان مستخدم في نسخة قديمة من المشروع).
- **مساعد دعم فني بالذكاء الاصطناعي** داخل لوحة التحكم، مبني على Claude (نموذج claude-haiku-4-5).
- تصميم عربي (RTL) بالكامل، متجاوب وموبايل-فيرست.
- PWA — يدعم "إضافة للشاشة الرئيسية" فيشتغل بشكل شبه كامل زي تطبيق موبايل حقيقي.
- حماية أساسية: تشفير كلمات مرور (scrypt)، حماية من محاولات الدخول المتكررة (rate limiting)، جلسات لها تاريخ انتهاء صلاحية.

## متغيرات البيئة المطلوبة (Environment Variables)

لازم تتحط في إعدادات المشروع على Vercel (Settings → Environment Variables) قبل أي تشغيل:

| المتغير | إجباري؟ | الوصف |
|---|---|---|
| `POSTGRES_URL` أو `DATABASE_URL` | ✅ إجباري | رابط الاتصال بقاعدة بيانات Neon Postgres (بيتحط تلقائي لو ربطت مشروع Neon من لوحة Vercel) |
| `ANTHROPIC_API_KEY` | اختياري | لتفعيل مساعد الدعم الفني الذكي. من غيره الميزة بتظهر رسالة "مش متفعّل حاليًا" بدل ما تعطّل باقي التطبيق |

## تشغيله محليًا للتطوير

يحتاج [Node.js](https://nodejs.org) الإصدار 20 أو أحدث، بالإضافة لمتغيرات البيئة اللي فوق (تقدر تحطها في ملف `.env` محلي وتستخدم أي أداة زي `dotenv` أو `vercel env pull` لو بتستخدم Vercel CLI).

```bash
node server.js
```

هيفتح على `http://localhost:3000`.

## رفعه أونلاين

المشروع مصمم للنشر على **Vercel** (فيه `vercel.json` جاهز):

1. اربط المشروع بـ Vercel (من GitHub أو مباشرة بـ Vercel CLI).
2. أضف قاعدة بيانات **Neon Postgres** من تبويب Storage في لوحة Vercel (أو اربط حساب Neon موجود بالفعل) — هيضيف متغيرات `POSTGRES_URL` تلقائيًا.
3. (اختياري) أضف `ANTHROPIC_API_KEY` لو عايز تفعّل الدعم الفني الذكي.
4. Deploy — مفيش أي build step مطلوب.

## هيكل المشروع

```
api/index.js         نقطة الدخول الفعلية على Vercel (الراوتر الرئيسي + الميدل وير)
server.js             إعادة توجيه بسيطة لـ api/index.js (Vercel بيدور على server.js كنقطة دخول افتراضية)
lib/db.js             الاتصال بقاعدة البيانات (Neon) وتعريف الجداول
lib/auth.js            تسجيل الدخول، الجلسات، تشفير كلمة المرور
lib/rate-limit.js       حماية من محاولات الدخول المتكررة وإساءة استخدام الدعم الفني
lib/view.js             قوالب HTML المشتركة (لوحة التحكم)
lib/kids-landing.js      صفحة بيع مخصوصة لفئة ملابس الأطفال
lib/themed-landing.js    صفحة بيع عامة قابلة للتخصيص لباقي الفئات
lib/category-configs.js  إعدادات كل فئة بيع (حقول، ألوان، نص الهيرو...)
lib/router.js            راوتر بسيط بيدعم :params
lib/body.js              قراءة بيانات الفورم (urlencoded / JSON)
routes/*.js              كل صفحة/قسم في ملف منفصل
public/                  CSS، JS، أيقونات، ملف الـ PWA
```

## نقاط مهمة قبل التسويق التجاري

راجع تقرير المراجعة التقنية الكامل — أهم نقطة لسه محتاجة قرار: **تخزين صور المنتجات** حاليًا بتتحول لـ base64 وتتخزن جوه قاعدة البيانات نفسها، وده هيبطّئ صفحات البيع مع زيادة عدد المنتجات. المفروض تتنقل لخدمة تخزين ملفات خارجية (Vercel Blob أو Cloudinary) قبل الإطلاق الفعلي على نطاق واسع.

## نقاط ممكن تتوسع فيها لاحقًا

- تصدير بيانات المبيعات/المخزون كملف Excel أو CSV.
- تقارير أرباح شهرية ورسوم بيانية.
- دعم أكتر من مستخدم لنفس المتجر (موظفين).
- نظام باقات واشتراكات مدفوعة لو هيتباع كخدمة شهرية (SaaS).
- ربط بوابة دفع أونلاين محلية (Paymob/Fawry) بدل/بجانب طلب الواتساب.
